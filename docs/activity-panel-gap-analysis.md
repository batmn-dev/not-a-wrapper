# Activity Panel Gap Analysis — ChatGPT reference → not-a-wrapper

## 1. TL;DR

The target app has **no Activity panel today** — reasoning, tool invocations, and sources all render *inline* in a single assistant message's vertical flex column (`app/components/chat/message-assistant.tsx:228-249` reasoning, `:251-287` tools, `:301` sources). The good news is the data is already cleanly parts-driven (`getSources(parts)` at `:102`, `useReasoningPhase({parts,...})` at `:127-138`), so the bulk of the work is **reuse, not rebuild**: existing primitives (`sheet.tsx`, `chain-of-thought.tsx`, `reasoning.tsx`, `badge.tsx`, `avatar.tsx`, `scroll-area.tsx`) cover the shell, timeline, chips, and favicons with additive CVA variants and one new leaf primitive. What genuinely must be *built* is a composition root that swaps a docked in-flow flyout (≥1024px) against a Sheet-backed card/bottom-sheet (<1024px), plus the plumbing to hoist reasoning/source state out of the per-message column into an active-turn-keyed panel. The plan below is staged: a **Step A** that is independently shippable with zero inline regression (tokens, additive variants, a Favicon primitive — all dormant behind existing call sites), then a **Step B** that is pixel- and behavior-exhaustive (responsive shell, hoisting, full variant set, a11y, dark mode).

### 6.7 Active-turn keying / regenerate / branch / duration-freeze — BEHAVIORAL SPEC

**Decision:** One panel, owned by one turn, keyed off the **server-selected path**. This is the linchpin of the no-flag clean cutover.

- **(A) Ownership.** The panel is owned by exactly one assistant turn: the **last assistant message on the server-selected path** — the assistant message whose index is the tail of the array returned by `projectSelectedPath(live, serverPath)` (`lib/chat-store/turns/selected-path.ts:171-180`). Ownership keys off that message's `message.id` (`activeTurnId`), **not** the raw live array and **not** any per-message `isLast`. `use-activity-panel.ts` derives `activeTurnId` from the projected path and feeds `{ phase, steps, sources, durationSeconds }` for that id into the single panel. (Today there is no owner — every assistant message renders its own reasoning/sources at `message-assistant.tsx:237-249,301`; hoisting REQUIRES inventing this owner.)
- **(B) `isLast` becomes active-turn-aware.** The live timer (`use-reasoning-phase.ts` `shouldRunTimer` / duration branch at `:75`, `:112`) runs only for `activeTurnId` **and** `phase === "thinking"`. All other assistant messages render frozen/persisted state.
- **(C) Duration freeze.** For the active **streaming** turn the live wall-clock timer governs (`setInterval` → `tickedSeconds`); on `phase` leaving `"thinking"` the effect cleanup freezes `tickedSeconds` to the final elapsed value (`:96-106`). For every **completed / non-active** turn, duration is the frozen persisted `metadata.reasoningDurationMs` (`Math.round(ms/1000)`), via the existing fallback (priority: live timer for the active turn > persisted for historical, `:108-124`).
- **(D) Regenerate.** Regenerating the last turn creates a new assistant sibling that becomes the selected path's tail; `activeTurnId` moves to the new `message.id`, its timer resets to 0 (render-sync reset `:78-83`) and runs live; the superseded sibling freezes to its persisted duration.
- **(E) Branch switch.** Selecting a different response/edit branch re-projects the selected path (`selectMessageBranch` → `projectSelectedPath`); `activeTurnId` recomputes from the NEW tail. The panel instantly shows that turn's persisted reasoning/sources/duration (no live timer unless that tail is itself still streaming). Branch nav anchors on the USER message and assistant messages render no branch control, so switching is a pure path re-selection the panel follows by id.
- **(F) C2 count-drift reconciliation.** `activeTurnId` MUST be computed against the **server-selected path via `projectSelectedPath`**, never the optimistic live count. During the brief client/server count-drift window (rapid multi-branch / edit version-guard), `projectSelectedPath` returns the **server path on divergence** (`isSelectedPathDivergent` → `serverPath`, else reconcile; `:171-180`) — so the panel may momentarily show the server's last-selected turn rather than an in-flight optimistic one. This is **correct and tolerated**: ownership follows the server-authoritative path and self-heals to the optimistic tail once live and server converge (`projectSelectedPath` is a no-op at convergence).

*Rationale:* keying ownership to the server-selected path tail is the only choice correct under the C2 edit version-guard count-drift edge, because `projectSelectedPath` is exactly the reconciler between optimistic live turns and the server-authoritative path. Duration mechanics are dictated by the existing hook (live wall-clock for the streaming turn, frozen on cleanup; persisted `metadata.reasoningDurationMs` otherwise). Confidence comes from pre-merge vitest coverage of phase transitions, duration freeze, persisted fallback, regenerate, and branch-switch path re-projection — **not** a runtime panel-vs-inline toggle. *(confidence: **strong**)*
