# Activity Panel Gap Analysis — ChatGPT reference → not-a-wrapper

## 1. TL;DR

The target app has **no Activity panel today** — reasoning, tool invocations, and sources all render _inline_ in a single assistant message's vertical flex column (`app/components/chat/message-assistant.tsx:228-249` reasoning, `:251-287` tools, `:301` sources). The good news is the data is already cleanly parts-driven (`getSources(parts)` at `:102`, `useReasoningPhase({parts,...})` at `:127-138`), so the bulk of the work is **reuse, not rebuild**: existing primitives (`sheet.tsx`, `chain-of-thought.tsx`, `reasoning.tsx`, `badge.tsx`, `avatar.tsx`, `scroll-area.tsx`) cover the shell, timeline, chips, and favicons with additive CVA variants and one new leaf primitive. What genuinely must be _built_ is a composition root that swaps a docked in-flow flyout (≥1024px) against a Sheet-backed card/bottom-sheet (<1024px), plus the plumbing to hoist reasoning/source state out of the per-message column into an active-turn-keyed panel. The plan below is staged: a **Step A** that is independently shippable with zero inline regression (tokens, additive variants, a Favicon primitive — all dormant behind existing call sites), then a **Step B** that is pixel- and behavior-exhaustive (responsive shell, hoisting, full variant set, a11y, dark mode).
